# Lecture narrative — working run of show

## Explicit build slides

Four launch slides are inserted into the sequence below:

- After the Past chapter title: **Build · Create the seminar document**. Discuss links and predict what survives without CSS/JavaScript while it runs.
- After Forms turn reading into action: **Build · Add the native voting form**. Discuss progressive enhancement and accessibility while it runs.
- After the Present chapter title: **Build · Make the room interactive**. Discuss partial updates and interaction tradeoffs; invite live votes once ready.
- After the Future chapter title: **Build · Compose a constrained interface**. Discuss stable versus generated interfaces while it runs.

Each slide projects its cue's actual application prompt. **Start this build** sends that displayed prompt with the selected model, only on an explicit click. Connect Codex first. Previous/Next never launches work. Navigation remains available while work runs; use the existing preview shortcut when a result is ready. A successful launch is guarded against duplicate clicks for that slide in this desk session. Resetting or reloading the desk clears this local guard.

The numbered outline below describes the discussion sequence; these four launch slides sit between its entries and share the surrounding time budget.

Target: 90 minutes including interaction, with up to 15 minutes of slack. Timings are guides, not deadlines. The web's evolution is the subject; agentic development is the live demonstration. Documents, applications and agents coexist.

Each chapter: establish a question, invite participation, inspect evidence. Show prompts deliberately; no slide starts a build. When builds take longer, use curated material or the prepared baseline. Do not narrate a wait.

## 1. Opening · title

**On screen:** Web development: past, present, and possible futures

Understand how the web evolved—and explore where it might go by building an application together.

**Private facilitation:** 00–03 · Establish the two threads: web history and direction, demonstrated through agentic development.

## 2. Opening · your experience

**On screen:** When you use the web today, what feels unnecessarily difficult?

Take at least two minutes to discuss with a neighbour. Choose one example to share.

Finding information · Repeating information · Navigating interfaces · Knowing what to trust

**Private facilitation:** 03–08 · Hear two examples. Remember them for the closing discussion. Use a show of hands if the room app is not ready.

## 3. Opening · shared experiment

**On screen:** We will build one application—and change how we use it.

You help choose the direction. An agent helps implement it. Together, we inspect what actually works.

**Private facilitation:** 08–12 · Explain the prepared template and recorded context. Invite a visual-theme choice. Show the real prompt before sending it; build in the background, not automatically.

## 4. Past · chapter

**On screen:** Past — Documents become interactive

How does a page communicate what we can do?

**Private facilitation:** 12–15 · Start Document A when ready. Use the hypermedia definition and diagram while it runs. These are overlapping approaches, not replacement eras.

## 5. Past · links

**On screen:** A link offers a next step.

An address identifies a resource. A link lets us reach it.

**Private facilitation:** 15–20 · Show a real link, its URL and browser navigation. Connect distributed information to the audience’s experience, rather than listing dates.

## 6. Past · predict

**On screen:** What will still work if we remove the styling and JavaScript?

Make a prediction before we try it.

**Private facilitation:** 20–24 · Take predictions, then inspect the running result. If the build is unfinished, inspect the prepared baseline.

## 7. Past · forms

**On screen:** Forms turn reading into action.

A form communicates an action, its inputs, and where the request will go.

**Private facilitation:** 24–29 · Start Document B using the prepared room. Explain native submission while it builds; inspect the actual request and response.

## 8. Past · enhancement

**On screen:** Keep the capability. Add the convenience.

Progressive enhancement starts with a working core, then adds presentation and richer interaction.

**Private facilitation:** 29–34 · Use the enhancement definition and layers. Test without JavaScript. Discuss keyboard access; semantic HTML alone is not proof of accessibility.

## 9. Past → present · improve

**On screen:** The capability works. What would make the interaction better?

Suggest one change—and explain who it would help.

**Private facilitation:** 34–38 · Gather suggestions. Carry one into the Present prompt; do not promise every suggestion will be implemented.

## 10. Present · chapter

**On screen:** Present — The browser becomes an application

What do we gain when the interface responds without a new page?

**Private facilitation:** 38–41 · Start the Present build. Show its prompt and explain what is preserved from the native form.

## 11. Present · shared experiment

**On screen:** One room. A changing result.

Make a choice. Watch how the shared view responds.

**Private facilitation:** 41–49 · Invite predefined votes once deployed and reachable. Compare two browser views. If unavailable, demonstrate locally without pretending the audience is connected.

## 12. Present · tradeoffs

**On screen:** What does faster feedback add—and what does it hide?

Compare the two versions. Name one benefit and one cost.

**Private facilitation:** 49–54 · Give frameworks credit. Discuss state, latency, failure and discoverability through the actual app, not a technology list.

## 13. Present → future · another client

**On screen:** A person can use this. What would another client need to understand it?

Think about the available actions, required input, and resulting state.

**Private facilitation:** 54–58 · Inspect the form or shared contract. Distinguish explicit actions from behavior that must be inferred.

## 14. Future · chapter

**On screen:** Future — Who constructs the interface?

Existing applications can become clearer to agents. Agents may also compose interfaces around services.

Two hypotheses that can coexist.

**Private facilitation:** 58–62 · Start constrained Future composition when inputs are ready. Explain that the agent building this app and an agent using it are different roles.

## 15. Future · stable or generated?

**On screen:** Which applications need a stable interface, and which could use a generated one?

Choose one example of each. What makes the difference?

**Private facilitation:** 62–70 · Give pairs two minutes, then discuss examples while the build runs. Use the two-directions diagram. This is a position, not a proven forecast.

## 16. Future · shared capability

**On screen:** Can people and agents use the same underlying capability?

Different interfaces need not mean independently maintained rules.

**Private facilitation:** 70–76 · Inspect the generated result and shared constraints. Explain the drift risk of duplicate contracts, without claiming separate APIs are always wrong.

## 17. Future · context

**On screen:** What context would improve this result—and what should remain private?

Name one useful piece of context and one boundary you would set.

**Private facilitation:** 76–83 · Show the actual context receipt. Distinguish aggregate audience choices from personal data; discuss profiling and incorrect assumptions.

## 18. Closing · return

**On screen:** If the interface changes, what should remain dependable?

Return to your opening frustration. Does what we built help—or move the problem somewhere else?

**Private facilitation:** 83–88 · Return to the examples students gave. Invite a counterexample to the shared-capability hypothesis.

## 19. Closing · next step

**On screen:** What would you investigate or build next?

One question. One counterexample. One practical experiment.

**Private facilitation:** 88–90+ · Leave space for students. Offer the free SDLCAI tickets as an optional continuation, not a required action. Use slack up to 105 minutes for discussion.
